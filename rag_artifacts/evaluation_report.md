## 🛠 Actionable Insights (План улучшений)

На основе полученных метрик, рекомендуется внедрить следующие улучшения в приоритетном порядке:

1. **Внедрить Гибридный поиск (Hybrid Search):** 
   - *Проблема:* Низкий Context Recall (0.500) указывает на то, что векторный поиск (FAISS) пропускает документы из-за лексического несоответствия (например, запрос "пеня", а в тексте "неустойка").
   - *Решение:* Добавить лексический поиск **BM25** (через библиотеку `rank-bm25` и `pymorphy3` для лемматизации) и объединить результаты с FAISS через **Reciprocal Rank Fusion (RRF)**.

2. **Ужесточить System Prompt для генерации:**
   - *Проблема:* В вопросах с низким Faithfulness модель пытается "угадать" ответ, если контекст слабый.
   - *Решение:* Добавить в промпт жесткое правило: *"Если в предоставленном контексте нет точного ответа на вопрос, отвечай строго: 'В предоставленных документах информация отсутствует'. Не используй внешние знания."*

3. **Улучшить чанкинг (Chunking Strategy):**
   - *Проблема:* Ключевая информация может "разрываться" на стыке чанков.
   - *Решение:* Попробовать увеличить `CHUNK_SIZE` до 1200-1500 или внедрить "Parent-Child Retrieval" (Small-to-Big), где ищутся маленькие чанки, а в LLM подается весь родительский документ.

4. **Добавить Query Rewriting (Переформулирование запроса):**
   - *Решение:* Перед поиском в FAISS пропускать вопрос пользователя через легкую LLM-модель для добавления юридических синонимов (например, "штраф" -> "штраф, неустойка, пени").
