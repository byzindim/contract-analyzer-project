## 🧠 Архитектурные выводы (Middle-Level Insights)

### 1. Подтверждение гипотезы о лексическом разрыве
Резкий рост Recall (с 0.50 до 0.59) доказывает, что чистый векторный поиск (FAISS) не справляется с юридической синонимией. BM25 успешно находит документы по точным совпадениям терминов (например, "инкассовые поручения", "Росаккредитация"), которые эмбеддинги `bge-m3` интерпретируют неточно.

### 2. Феномен Recall-Faithfulness Trade-off
Падение Faithfulness (с 0.71 до 0.58) — это классическая проблема гибридного поиска. 
**Причина:** RRF с равными весами (1.0 для FAISS и 1.0 для BM25) подмешивает в топ-3 "шумовые" документы, найденные BM25 по случайным совпадениям слов. LLM (Qwen 2.5-7B) видит противоречивый контекст и начинает галлюцинировать.

### 3. План дальнейших улучшений (Roadmap)
Для вывода системы в Production необходимо внедрить:
1. **Weighted RRF:** Уменьшить вес BM25 (например, `weight_bm25 = 0.5`), чтобы снизить долю шума.
2. **Cross-Encoder Reranker:** Добавить третий этап — переранжирование топ-10 документов с помощью модели `ms-marco-MiniLM` (или локального аналога), чтобы отсечь шум перед подачей в LLM.
3. **Metadata Filtering:** Использовать извлеченные метаданные (контрагент, тип документа) для жесткой фильтрации до поиска в FAISS/BM25.
